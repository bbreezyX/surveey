# Optimasi lanjutan LCP dan loading awal

Pekerjaan lokal di `/Users/dany/WEB-DEV/surveypjuts`, branch `master`,
3 November 2026. Baseline adalah **hasil optimasi pertama dalam chat ini**,
bukan commit bersih `d4d886a`. Tidak ada commit, push, atau deployment.

## Bottleneck dan perubahan

1. Miniatur wilayah menghasilkan satu elemen SVG untuk setiap titik. Kini titik
   dengan style yang sama dan berurutan digabungkan ke dalam path. Semua koordinat,
   urutan status, dan lingkaran penanda titik terpilih tetap diwakili. Pada layar
   awal, jumlah elemen DOM turun **792 → 310** (60,9%). Pin pada peta utama tidak
   digabungkan oleh perubahan ini.
2. Penulisan `scrollTop = 0` pada mount sidebar memaksa browser menghitung layout
   padahal scroller baru sudah berada di posisi nol. Penulisan awal dihilangkan;
   perubahan wilayah, filter, dan pencarian tetap mengembalikan scroll ke atas.
3. Inisialisasi OpenLayers sebelumnya berjalan dalam pekerjaan mount Svelte yang
   sama dengan sidebar. Kini satu animation frame diikuti task timer memberi
   browser kesempatan menampilkan shell terlebih dahulu. Setup memakai state
   terbaru, dibatalkan saat unmount, dan effect lokasi menunggu adapter tersedia.
   `aria-busy` menunjukkan adapter belum siap.

Trace CPU/layout awal digunakan untuk menemukan jalur tersebut; profiler tidak
diaktifkan selama perbandingan akhir. Optimasi ini mengurangi pekerjaan render
dan mengubah urutannya, bukan mengurangi ukuran unduhan JavaScript: entry gzip
142.636 → 142.742 byte (+106 byte, memakai pengaturan gzip Node yang sama).

## Pengukuran sebelum–sesudah

Lima run per versi, urutan bergantian, Chromium dengan viewport 390×844, DPR 3,
CPU slowdown 6×, latency 150 ms, download 1,6 Mbps, upload 750 Kbps. Setiap run
memakai browser context baru. HTTP gzip dan cache aset immutable aktif; service
worker diblokir. Tile/progres eksternal memakai fixture deterministik dan data
lokal sama. Tidak ada build atau suite test yang berjalan selama benchmark.

| Ukuran | Sebelum, median | Sesudah, median | Perubahan |
| --- | ---: | ---: | ---: |
| LCP teramati | 3.812 ms | 2.992 ms | −21,5% |
| Total dan canvas peta tersedia + 2 frame | 4.792 ms | 4.679 ms | −2,4% |
| Akumulasi blocking awal | 2.050 ms | 1.930 ms | −5,9% |
| FCP | 2.128 ms | 2.136 ms | +8 ms |
| Pencarian JAMBI, 143 hasil | 722 ms | 676 ms | −6,4% |
| Elemen DOM awal | 792 | 310 | −60,9% |
| Jumlah layout shift teramati | 0 | 0 | Tetap |

Rentang LCP: sebelum **3.768–3.832 ms**, sesudah **2.984–3.000 ms**.
Rentang canvas tersedia: sebelum 4.785–4.908 ms, sesudah 4.516–4.774 ms.
LCP membaik pada kelima pasangan run, tetapi ini tetap hasil lab satu mesin,
bukan persentil pengguna atau bukti Android fisik. Waktu pencarian sesudah
bervariasi 646–815 ms; perubahan median kecil ini tidak dijadikan klaim INP.

Kandidat LCP terbesar pada kunjungan baru adalah teks petunjuk geser peta.
Petunjuk tetap tampil; perbaikan berasal dari kesempatan render lebih awal.
Angka canvas tersedia dipisahkan karena LCP ini tidak mengukur selesainya citra
basemap. Canvas WebGL/2D sendiri juga bukan kandidat LCP. Petunjuk dapat ditutup
dengan interaksi dan punya durasi otomatis 3,3 detik; waktu canvas tersedia tidak
berarti petunjuk sudah hilang atau semua tile jaringan sudah selesai.

Akumulasi blocking dihitung sebagai jumlah `max(0, durasi long task − 50 ms)`
untuk task yang mulai sebelum kondisi canvas tersedia. Ini **bukan Lighthouse
TBT**. Pengukuran pencarian mencakup automation dan dua animation frame, **bukan
INP**. Observasi LCP berhenti satu detik setelah kondisi canvas tersedia, sebelum
input pencarian. Tidak ditemukan error JavaScript atau horizontal overflow pada
sepuluh run.

Angka baseline ini tidak boleh dibandingkan langsung dengan tabel audit pertama:
batch, baseline, dan harness berbeda. Harness lanjutan menggunakan cache aset
immutable dan mengaktifkan cache browser setelah request routing diatur;
perbandingan yang sah adalah kolom sebelum–sesudah di batch yang sama.

## Validasi

- `npm run build` berhasil: Svelte/TypeScript 0 error dan 0 warning.
- `npm test`: **55 tes lolos**, 13 file.
- `npx playwright test tests/browser/public-map.spec.ts tests/browser/lifecycle.spec.ts`:
  **72 lolos, 6 skip**, Chromium/WebKit/Firefox. Tiga skip memerlukan Caddy produksi
  dan tiga memerlukan key Google pada build. Tidak ada kegagalan pada run ini.
- Cakupan mencakup linked point, popup ponsel, pencarian, posisi pin, focus,
  perubahan breakpoint, refresh progres, DPR 3, retry data, serta mount/unmount.
  Tes baru memastikan shell ada sebelum setup peta dan callback tertunda tidak
  memasang peta setelah komponen di-unmount. Tes SVG mencakup titik berimpit dan
  urutan status.
- Tampilan desktop dan ponsel diperiksa dari screenshot build produksi lokal.
  Pemeriksaan ini tidak mengukur kecepatan unduh tile produksi.
- Suite backend/admin dan jaringan/offline tidak diulang pada tahap lanjutan;
  hasil tahap pertama tetap tercatat dalam laporan audit sebelumnya.

## Beban yang masih tersisa

- FCP sekitar 2,13 detik hampir tidak berubah. Entry aplikasi masih sekitar
  465 KB mentah / 143 KB gzip; tahap ini belum mengubah transfer dan parsing bundle.
- Akumulasi blocking masih sekitar 1,93 detik. Pembuatan layer, feature, label,
  dan render canvas OpenLayers masih membutuhkan main thread; penjadwalan ulang
  membuat shell lebih cepat terlihat tetapi tidak menghilangkan semua pekerjaan itu.
- Canvas tersedia sekitar 4,68 detik dalam profil lambat. Kesiapan citra satelit
  nyata masih bergantung pada layanan tile dan jaringan, yang tidak diukur di sini.
- Pengujian pada HP fisik dan pengukuran pengguna produksi belum dilakukan.
  Pemisahan bundle OpenLayers perlu eksperimen tersendiri: berpotensi mempercepat
  shell, tetapi request tambahan dapat memperlambat peta pada jaringan lambat.

## Artefak dan reproduksi

[Data mentah, median, rentang, parameter, dan hash build](2026-11-03-loading-results.json).
[Audit tahap pertama](2026-11-03-audit.md).

```sh
node scripts/measure-public-loading.mjs \
  .superpowers/lcp-2026-11-03/baseline \
  dist/public \
  .superpowers/lcp-2026-11-03/repeat-comparison.json
```

Baseline build disimpan lokal di folder `.superpowers` yang diabaikan Git.
Pada checkout lain, siapkan dua build yang hendak dibandingkan dan masukkan
path-nya sebagai dua argumen pertama. `PERF_RUNS` mengatur jumlah run per versi
(default 5). Profil CPU, trace layout, dan screenshot juga tersimpan lokal di
`.superpowers/lcp-2026-11-03/`. Skrip dan data hasil ringkas disertakan dalam
perubahan yang dapat di-commit.
